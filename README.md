# Human–AI Contribution Provenance

> Working name: Human–AI Contribution Provenance (HACP)

**HACP** is an experimental open specification for describing how humans and generative AI contributed to digital content.

Instead of reducing content provenance to a binary question such as:

> "Was this generated by AI?"

HACP describes the roles played by humans and AI systems.

For example:

- a human provided the original idea and expertise,
- an AI system helped structure the content,
- an AI system improved wording,
- a human reviewed and approved the final result.

The goal is **not** to detect AI-generated content.

The goal is to make AI involvement transparent, structured and verifiable.

## Why?

The distinction between "human content" and "AI-generated content" is increasingly insufficient.

### Human authored

A person writes an article without generative AI assistance.

### AI assisted

A person provides the idea, expertise and facts.

An AI system helps with:

- grammar,
- wording,
- structure,
- translation.

### Human–AI collaboration

A human and an AI system jointly develop:

- arguments,
- structure,
- examples,
- wording.

### AI generated

A system generates most or all of the content from a prompt with little human involvement.

These scenarios should not be represented by the same label.

## Example

```json
{
  "specVersion": "0.1",
  "origin": "human",
  "aiInvolvement": "assisted",
  "humanReviewed": true,
  "contributions": {
    "human": [
      "concept",
      "expertise",
      "facts",
      "review"
    ],
    "ai": [
      "structure",
      "wording"
    ]
  },
  "generator": {
    "provider": "OpenAI",
    "model": "GPT-5.6"
  }
}
```

This describes content where the intellectual origin remains primarily human while an AI system acts as an editing and writing assistant.

## Goals

HACP aims to provide:

- a machine-readable description of human and AI contributions,
- a simple vocabulary for different forms of AI assistance,
- optional cryptographic verification,
- compatibility with web publishing and content provenance systems,
- a vendor-neutral format.

Potential consumers include:

- publishers,
- CMS platforms,
- search engines,
- browsers,
- AI providers,
- content verification tools,
- archives,
- academic systems.

## Non-goals

HACP is **not** intended to:

- determine whether a text "looks AI-generated",
- replace plagiarism detection,
- determine whether content is true,
- determine whether content is high quality,
- punish the use of generative AI,
- act as an SEO ranking signal.

HACP describes provenance.

How consumers interpret that provenance is outside the scope of the specification.

## Trust model

HACP separates **claims** from **proof**.

A provenance manifest can say:

> "The original concept was created by a human."

That statement alone does not prove that the claim is true.

A cryptographic signature can prove:

> "Publisher X signed this exact provenance declaration for this exact content."

Future versions may support multiple attestations from publishers, AI providers, editors and content platforms.

## Design principles

HACP should remain:

- open,
- vendor neutral,
- simple,
- extensible,
- human readable,
- machine readable,
- privacy preserving.

## Status

HACP is currently an experimental **v0.1 proposal**.

The specification is intentionally small.

Feedback, criticism and alternative approaches are welcome.
